# 玩家记忆

玩家记忆服务于同一个玩家的持续使用：保留常玩定位、回答偏好、练习目标和用户自己记下的经验；下一次只召回与当前游戏、问题有关的部分。入口为 `/memory/`，游戏助手与三款小游戏的分析结果都可以展开“这次用到的记忆”。

## 存储与生命周期

- 玩家档案仍由 SQLite-first `MongoStore` 保存，MongoDB 为已有档案、分析历史、反馈提供可选副本。
- 新的个人提醒、游戏目标、复盘经验、已复盘的小游戏终局保存在同一 SQLite 文件的 `player_memories` 表中，按 `user_id` 和游戏范围建立索引；这些新条目不复制到 MongoDB。默认文件是 `backend/data/gamebuddy.sqlite3`，可通过 `GAMEBUDDY_DATA_DIR` 指定持久化目录。
- 同一个玩家、游戏范围、类型、key 对应一条当前记忆。更新使用 `expected_revision`，旧页面更新会返回 409，不会悄悄覆盖新内容。
- 每个玩家最多 200 条条目，可设置 1–365 天有效期。过期条目在该玩家下一次读取或写入时物理清除；删除会移除当前内容。
- 小游戏只在本地或管理员对已结束的一局调用分析时记录终局，默认保留 30 天。同一局重复分析不会重复记录或延长保留期。删除后，同一局的再次分析也不会重新生成记录；短期保留的删除标记只有玩家、范围、局标识和到期时间，没有被删内容。
- 条目删除针对玩家记忆表；既有 Trace、人工反馈、原始分析历史是独立记录，不随一条提醒的删除一并清空。

## 写入与更新

档案可以在记忆页面编辑。`POST /memory/profile` 替换档案；`PATCH /memory/profile/{user_id}` 只更新提交的字段，未提交字段继承，显式 `null` 或 `[]` 清空旧值。仅传 ID 的分析请求不会重新写入已加载的档案，也不会把游戏专属目标存成通用目标。

只有完整的显式表达 `记住：…` 或 `remember: …` 才会从问答中写入长期记忆：

- `记住：我主玩辅助` 更新常玩定位。
- `记住：回答简短一点` 更新回答风格，后续本地知识问答只展示一条知识引用。
- `记住：我的目标是练视野` 保存当前游戏的目标；`我的目标改成…` 更新同一目标。
- 其他明确请求保存为该游戏下的个人提醒，重复内容去重。

不会从普通聊天、队友发言、模型回答、单局血量或金币推断长期玩家特征。用户也可以手动新增、修改和删除个人提醒、目标及复盘经验。

## 召回与实际使用

1. 先按玩家 ID 和游戏过滤；当前游戏的同名条目优先于通用条目。
2. 使用现有中英文术语映射、词项相关度和轻量时间衰减排序，最多召回 4 条提醒/目标。
3. 从该玩家当前游戏最近 100 条分析历史中选择最多 2 段相关的用户原始事件；不将模型推断出的失误当成事实。小游戏终局作为带时间的独立历史片段召回，并排除当前局本身。
4. 提醒与历史片段的内容合计不超过 1400 字符；玩家档案单独限制为有界字段、最多 10 个目标和 10 条备注。
5. 档案偏好影响本地解释和回答长度，游戏目标进入练习建议，提醒及历史事件进入复盘练习方向。记忆不会覆盖当前棋盘规则或把过去事件当成当前事实。
6. 响应 `metadata.memory` 给出实际采用的档案字段、条目 ID、相关原因和旧事件时间；Trace 包含独立 memory 阶段，便于检查一次召回的输入与输出。

本版采用本地记忆处理。识别到长期玩家记忆的请求不会发往 OpenRouter，即使已配置模型 Key；响应会标记 `private_memory_local_only`。无记忆请求仍遵循原有模型配置。当前没有新增 Embedding 服务、向量数据库或模型训练。

## 访问与接口

新增接口均在原有本地/管理员访问边界内，响应使用 `Cache-Control: no-store`。这是单管理员环境中的玩家数据分组，不是多租户登录鉴权。公开匿名访问保持无状态，不读写玩家记忆；线上免费实例仍保持已选择的公开模式。

- `GET /api/v1/memory/items?user_id=...&game=...`：读取当前条目，游戏参数可选。
- `POST /api/v1/memory/items`：`{user_id,game?,kind,key,content,ttl_days?,expected_revision:0}`。
- `PUT /api/v1/memory/items/{id}`：`{user_id,content,ttl_days?,expected_revision}`。
- `DELETE /api/v1/memory/items/{id}?user_id=...&expected_revision=...`：删除条目，返回 204。
- `PATCH /api/v1/memory/profile/{user_id}`：档案局部更新。
- `/api/v1/play/analyze` 增加可选 `player_id`、`run_id`；只有本地/管理员请求使用它们。

验证覆盖持久化、跨会话效果、游戏/玩家分组、来源、修改冲突、删除与过期、内容预算、旧草稿覆盖、终局去重、公开访问限制与外部模型不接收记忆。这些检查不代表胜率或模型能力提升。
